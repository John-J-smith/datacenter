# 参变量 RAM 合成一块并加头尾标记

| 版本 | 日期 | 说明 |
|------|------|------|
| v1.0 | 2026-09-08 | 与变量类同一套「头尾好则信 RAM」 |
| v1.1 | 2026-09-08 | 上电对齐 var_ensure_init：先查块校验，不因头尾对而跳过 |

## 要解决什么

现在每个带 RAM 的参变量块是单独一个全局变量（`g_param_ram_0`、`g_param_ram_1` …）。复位后是否还是上次的内容，全靠各块自己末尾 2 字节校验。

变量类已经是：一块连续 RAM，A/B 区前后各有 32 位标记。标记对就当 RAM 没被冲掉，不再先查校验。

参变量要做成同样的用法：**所有带 RAM 的块放进同一个带头尾标记的结构**。

## 不做

- 不给整块 RAM 再加一份总校验（仍用每块末尾 2 字节）。
- 不把「只存在 EEPROM、没有 RAM」的块放进这个结构。
- 不按存储种类拆成两套头尾（不是变量里的 A 区和 B 区各一套）。
- 不把 RAM 里每块垫满一页大小；仍用现在的紧凑块长度。

## 内存长什么样

生成工具写出一个结构（名字可按仓库匈牙利习惯，例如 `ST_PARAM_SRAM`），大致为：

- 开头 4 字节：头标记（建议宏 `PARAM_SRAM_MAGIC_HEAD`，数值可与变量头相同 `0xA5A5A5A5`）
- 中间：按块表顺序嵌套现有 `param_layout_N_t`（测试清单里是 0–4，接着 11–15）
- 末尾 4 字节：尾标记（`PARAM_SRAM_MAGIC_TAIL`，数值可与变量尾相同 `0x5A5A5A5A`）

整个对象加 `DC_NOINIT`，产品可放到不复位清零的段。

块表里「RAM 指针」改为指向结构里对应成员，不再生成一串独立的 `g_param_ram_N`。

## 上电初始化（对齐 `var_ensure_init`）

第一次进入时**必须查每一块带 RAM 的块尾校验**，**不能因为头尾已经对就跳过**。和变量一样：先看数据校验，再决定要不要补头尾。

对每个带 RAM 的块：

1. 块尾校验不对 → EEPROM 主槽 → 备份槽（若有）→ 出厂默认或 0xFF。默认仍不写 EEPROM。
2. 该块校验对了（本来就对，或刚恢复成功），扫完所有带 RAM 的块之后，若头尾还不对则补头尾。
3. 某块恢复后校验仍不对：该块按现在规则填默认；**还有块校验不对时，不要把头尾写成合法**。全部带 RAM 的块校验都对了，才写头尾。

没有 RAM 的块：仍按块从 EEPROM / 默认装进临时缓冲，与头尾无关。

## 之后每次读/写（对齐变量「访问前」）

初始化已经做过之后，对**带 RAM** 的参变量：

1. 头、尾都对：认定 RAM 没被冲掉，**不再查块校验**，直接读/写。写完只改**当前这一块**末尾校验，并按现有规则写 EEPROM。
2. 头或尾不对：再对每一个带 RAM 的块查校验；错的走主槽 → 备份 → 默认。全部处理完，且各块校验都对了，再把头尾写回去。

没有 RAM 的块：仍不看头尾。

## 生成工具与文档

- `dc_param_pack` 生成上述结构、块表指针、头尾宏。
- 分类消耗里的 RAM 字节数 = 头尾 8 字节 + 各带 RAM 块的紧凑长度之和。
- `dc_layout.md` 用一句话说明：带 RAM 的参变量共用一块带头尾的 RAM。

## 测试

- **上电 / 重新 init**：RAM 里块校验已坏，即使头尾仍对，也应从 EEPROM（或默认）拉回来，不能信坏数据。
- **上电**：校验对、头尾不对 → 补头尾，数据保持 RAM。
- **上电**：校验不对且 EEPROM 也坏 → 填默认；各块都合法之前不要把头尾写成「好」。
- **init 之后**（运行中）：头尾都对，再改坏某一块校验 → 再读应仍是 RAM 里的值（此时不查块校验）。
- **init 之后**：弄坏头尾、块校验仍对 → 再读数据不变，头尾被补上。
- 现有默认值、读写、主槽/备份用例继续通过。
- 测试 hook 至少能：冲掉头尾、冲掉指定块校验。

## 成功标准

- 生成头里不再出现多个独立的 `g_param_ram_N`。
- 行为与上文「上电」和「之后每次读/写」一致。
- `dc_tests` 全绿。
